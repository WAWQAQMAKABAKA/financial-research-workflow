- Real canonical text integrity
- Exact retrieval hit source bindings
- P2 structural recovery with curated table anchors
- Conservative date-level PIT representation
- In-memory transport through FRW EvidenceItem and
  EvidencePacket contracts

Not demonstrated:
- Independent automatic table detection
- Question-specific financial proposition support
- Independent evidence sufficiency adjudication
- Historical source revision-as-of verification
- Real live EvidenceProvider enforcement
- Actual-source execution through LangGraph
- Production alerting, research delivery or trading
- Generalization to other companies, documents,
  report layouts or questions

The original FRW LangGraph and the Retrieval Lab
baseline were not modified in S5A–S5F.

## 8. Follow-up engineering boundary

Do not promote manually curated candidate spans into
an automatic production table detector.

Any future Evidence Service adapter must enforce
PIT admission, actual acquisition constraints,
document/version provenance and explicit unavailability.

A production path must distinguish:
- no relevant retrieval hit,
- failed table association,
- valid contextual evidence,
- proposition-level evidence support,
- question-level evidence sufficiency,
- technical unavailability.

Only after each boundary is verified should actual
source-backed evidence enter the existing FRW Graph.

S5A–S5F are development execution findings,
not a release qualification.
